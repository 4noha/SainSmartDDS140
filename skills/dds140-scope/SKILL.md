# DDS140（USB オシロ）を扱う

実装は `~/works/tools/SainSmartDDS140`（Python + pyusb、macOS/Windows 共通）。
プロトコルの詳細はそのリポジトリの `docs/protocol.md` にある。**ここには
「使うとき・壊さないために必要なこと」だけ**を書く。

## まず動かす

```sh
cd ~/works/tools/SainSmartDDS140

python3 -m dds140 info                 # 認識しているか + コマンドの自己診断
python3 -m dds140 cal                  # 個体キャリブレーション値
python3 -m dds140 monitor              # 数値をライブ表示（プローブ確認に最適）
python3 -m dds140 capture --samples 16384 --skip 16 --svg w.svg   # 1 フレーム
python3 -m dds140 ui                   # ブラウザ UI（http://127.0.0.1:8765/）
```

引数なしで困ったら `python3 -m dds140 <cmd> --help`。

## これを知らないと数字を間違える（実測済みの事実）

1. **サンプルレートのラベルは実測値ではない。**
   `--rate 100M` の実際は **約 3.58 MS/s**（USB 帯域で頭打ち）。
   10M→447 kS/s、625k→28 kS/s。校正値は `~/.dds140/rates.json` にあり、
   `Scope` が自動で使う。**校正ファイルを消すと時間軸が 22〜28 倍ずれる。**
   作り直すには内蔵 1 kHz 矩形波を当てて `python3 -m dds140 calib-rate`。

2. **フレーム先頭の 2〜10 サンプルは整定で跳ねる。** `--skip 16` を付ける。
   付けないと無入力でも 1〜7 V 相当のスパイクが見える。

3. **時間軸と周波数を信用できるのは `--rate 100M` だけ**（転送が実時間と同じ）。
   他のレートはデータが速く届きすぎていてサンプル欠落がある。

4. **`--rate 200M`（合成）は ADC のインターリーブではない。**
   データは 2ch のまま、実効レートも 2ch と同じ。名前だけの設定。

5. **読み出し長は 32 KiB の倍数**。半端だと libusb が Overflow で落ちる
   （実装側で吸収済み）。

6. **レンジ切替は基板のリレーが鳴る**（正常）。CH1/CH2 は独立した
   フロントエンドなので、片方のレンジを変えても他方は変わらない。

7. **電圧の絶対値は補正なしだと 10% 近くずれる**（レンジ間で 9.2% ばらつく）。
   補正値は `~/.dds140/ranges.json`。有効にするときだけ `DDS140_VCAL=1` を付ける。
   校正は `python3 -m dds140 calib-range --reference-pp 1.5`（内蔵矩形波を基準）。

## 記録

```sh
python3 -m dds140 record --capacity                        # レートごとの上限
python3 -m dds140 record --rate 100M --seconds 5 -o captures/r.bin --csv
```

- 「連続した記録」が成立するのは、転送が実時間と一致する設定だけ
  （実質 `--rate 100M`）。`record` は `realtime_factor` を出し、
  3 倍を超えると「実時間で連続していない可能性」と警告する。
- 1 フレームの上限は 40 MB（= 2000 万サンプル/ch）。超える要求は切り詰められる。

## プローブが届いているか疑うとき

```sh
python3 -m dds140 input-check --spectrum   # レンジ依存性で「本物の信号か」を判定
python3 -m dds140 spectrum --rate 100M --f-lo 800 --f-hi 1200 --step 2
```

- `input-check`: 本物の信号はレンジを変えても AC RMS が変わらない。
  ADC ノイズやドリフトはレンジ（ゲイン）に比例して変わる。
- 内蔵の 1 kHz 標準矩形波（BNC と BNC の間の**小さな金属ピン**、約 1.5 V）は
  プローブと基板の健全性確認に最適。**信号発生器モジュールを挿すと無効になる**ことがある。
- 1x プローブ + GND クリップで測る。1x は ±5V、10x は ±50V が定格。

## 触ってはいけないもの

- **EEPROM（24LC64I）への書き込み・ファーム差し替え**。復旧手段がない。
- **基板のジャンパ J1 を外す**。`04b4:8613`（Cypress ブートローダ）で上がり、
  ベンダ FW を戻さないと動かなくなる。
- 未確認のコマンドを総当たりで送る（設定が飛ぶと戻せない）。

## 困ったとき

| 症状 | 見るところ |
|---|---|
| `8312:8312` が見えない | 直挿し（バスパワー 500mA）、`04b4:8613` なら J1 が外れている |
| `Resource busy` | 他プロセス（UI や古い python）が掴んでいる。`pkill -f "dds140"` |
| 取得待ちがタイムアウト | 240k/39k は status 33 まで数秒かかる。`--poll-timeout` を伸ばす |
| 周波数が 20 倍ずれる | `~/.dds140/rates.json` が無い/古い → `calib-rate` をやり直す |
| 振幅がレンジで変わる | `DDS140_VCAL=1` を付ける（校正済みなら）。無ければ `calib-range` |
