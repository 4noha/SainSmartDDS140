# 信号の記録

2026-10-31 に macOS 実機（`8312:8312`）で測った結果。

## できること

```sh
# 1 フレームを長時間とる（連続記録に相当）
python3 -m dds140 record --rate 240k --seconds 10 -o captures/rec.bin

# 何秒とれるか（レートごとの上限）
python3 -m dds140 record --capacity

# 速いレートで「スナップショットを何枚も」とる（フレーム間は空く）
python3 -m dds140 record --rate 100M --samples 65536 --frames 20 -o captures/multi.bin

# .bin から CSV を作る
python3 -m dds140.record  # 相当は record の --csv
```

UI からも記録できる（右パネルの「● 記録 (REC)」）。
`captures/ui-YYYYmmdd-HHMMSS.bin` に保存され、`.bin` / `.csv` をダウンロードできる。

保存形式:

- `*.bin` … **交互配置の生バイト**（`CH1, CH2, CH1, CH2, ...`、8 bit）
- `*.bin.json` … メタデータ（レート、レンジ、キャリブレーション、フレームごとの
  バイト位置・サンプル数・転送時間）
- `*.bin.csv` … 任意で書き出す CSV（`frame,time_s,ch1_code,ch2_code`）

生バイトを残すのは、電圧換算の係数（キャリブレーション）が個体で変わるため。
あとから `*.bin.json` の値で何度でも換算し直せる。

## 実測した上限

1 フレームで要求できるのは **40 MB（= 2,097万サンプル/ch）** まで
（それ以上は `record` が切り詰める。ベンダ DLL の内部バッファは 20 MB だが、
実機では 40 MB まで受信できた）。

| レート | 1 フレームの長さ（40 MB 時） | 転送時間 | 実時間で連続か |
|---|---|---|---|
| 100 MS/s | 0.21 s | 0.7 s | ✗（USB 帯域で決まる） |
| 10 MS/s | 2.10 s | 0.7 s | ✗ |
| 625 kS/s | 33.6 s | 1.0 s | ✗（速すぎる） |
| 240 kS/s | 87.4 s | 87 s | **✓（転送が実時間と一致）** |
| 39 kS/s | 537.7 s | 3〜8 s | ✗（速すぎる） |

**「実時間で連続」の判定**: データ長（サンプル数 ÷ レート）と実際の転送時間が
一致していれば、デバイスは実時間でサンプルを吐いている（= 途切れがない）。
`record` はこれを `realtime_factor`（データ長 ÷ 転送時間）として記録し、
3 倍を超えると警告を出す。

- 240 kS/s は実測で `realtime_factor ≈ 1.00`。**連続記録はこれを使う。**
- 39 kS/s / 625 kS/s / 100 MS/s は転送が速すぎるので、届いたサンプルが
  実時間で連続している保証がない（デバイス内部で間引いている可能性）。
  波形の形は見られるが「○秒ぶんの連続記録」と主張できない。

## わかった落とし穴

1. **読み出し長は 32 KiB の倍数にする。**
   半端な長さで読むと `libusb: Overflow`（macOS の `kIOReturnOverrun`）になる。
   `Transport.read_frame()` は 32 KiB に切り上げて読み、余分を捨てている。
2. **`cmd 51` のあと status 33 まで待つ時間がレートで大きく違う。**
   240 kS/s は約 6.7 秒、39 kS/s は約 1.7 秒、100 MS/s は 0.02 秒。
3. **フレーム先頭の数サンプルは整定で跳ねる。**
   記録では `--skip 0`（既定）にして連続性を保つ。表示だけなら `--skip 16`。
4. 記録中は UI のライブ表示が止まる（USB を 1 本のスレッドで使っているため）。

## 未検証

- 39k / 625k モードの**実際のサンプルレート**。既知の信号（1 kHz など）を
  入力して、周期から真のレートを校正する必要がある。
- 100 MS/s でフレームを連ねたときの取りこぼし量（フレーム間の空白）。
- 200 MS/s 合成モードでの記録。
